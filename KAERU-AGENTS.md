# kaeru — память между сессиями

У тебя есть инструменты `kaeru` — это твоя память, которая переживает конец
сессии. Всё, что не записано туда, ты забудешь навсегда.

## 4 правила, которые нарушать нельзя

1. **В каждый вызов передавай `initiative`** — имя проекта (репозиторий, тема).
   Без него записи теряются, а поиск лезет во все проекты сразу. Не спрашивай
   у пользователя, какой initiative — выведи из контекста.
2. **Пиши и ищи по-русски.** Не переводи на английский ни при записи, ни при
   поиске. Перевод = ничего не найдётся.
3. **Никогда не спрашивай разрешения сохранить.** Не пиши «записать это в
   память?». Считаешь важным — просто пиши.
4. **Не пиши мусор.** Каждая реплика в память не идёт. Идут: решения, находки,
   предпочтения пользователя, результаты, факты о проекте.

## Начало работы над проектом

```
initiatives()                      → список проектов
awake(initiative: "имя")           → что было открыто в прошлый раз
```

Этого достаточно. `overview(initiative)` — если нужна карта проекта целиком.

## Что чем сохранять

Выбирай по типу содержимого, не по длине.

| Инструмент | Когда | Пример |
|---|---|---|
| `jot(body)` | мимолётная заметка, имя не нужно | «сборка падает без LIBCLANG_PATH» |
| `episode(name, body)` | наблюдение по текущей работе, захочешь найти по имени | «Сборка kaeru на машине Сбера» |
| `cite(name, body)` | устоявшийся факт, решение, документ. `url` необязателен | «Порт kaeru-mcp по умолчанию 9876» |
| `task(body, due)` | задача на потом | «проверить rustc на целевой машине», `due: "3d"` |
| `done(name)` | задача выполнена | |

`jot` и `episode` — рабочая память, она устаревает. `cite` — архив, то, что
останется.

## Память, которая всегда в контексте

У всех инструментов записи есть параметр `layer`. По умолчанию `warm`.
`layer: "core"` = попадает в контекст при каждом `awake`, без ограничения по
объёму.

```
cite(name: "...", body: "...", initiative: "...", layer: "core")
layer(name: "...", layer: "core")     ← перевести существующий узел
```

**Используй `core` очень скупо** — 3–5 узлов на проект. Туда идёт только то, что
нужно вообще всегда: ключевое решение по проекту, стиль работы, который просил
пользователь, глоссарий. Всё остальное оставляй как есть.

## Поиск

```
search(query: "...", initiative: "...")   → полнотекстовый поиск
recall(name: "...")                       → найти по точному имени
drill(name: "...")                        → раскрыть узел и его источники
```

`search` не умеет словоформы. Ищи `утечк*` вместо `утечка`, `сборк*` вместо
`сборке`. Звёздочка в конце — почти всегда правильно.

## Связи

```
link(from: "A", to: "B", initiative: "...")
link(from: "A", to: "B", strong: true)    ← ключевая связь
```

Связывай находку с тем, к чему она относится. Одинокие узлы потом не находятся.

## Гипотезы

Когда что-то предполагаешь, но не проверил:

```
claim(text: "предположение")       → записать гипотезу
confirm(hypothesis: "...", by: "имя узла с доказательством")
refute(hypothesis: "...", by: "имя узла с опровержением")
```

## Чего не делать

- Не заводи локальные файлы-заметки и TODO.md — для этого есть kaeru.
- Не спрашивай «сохранить ли это».
- Не переводи содержимое на английский.
- Не забывай `initiative`.
- Не ставь `layer: "core"` всему подряд.

## Короткий пример

```
awake(initiative: "kaeru")

# нашёл важное
cite(
  name: "Сборка требует MSVC Build Tools и libclang",
  body: "Одного rustc не хватает: RocksDB собирается из C++, zstd-sys гонит bindgen.",
  initiative: "kaeru",
  layer: "core"
)

# по ходу дела
jot(body: "AWS_LC_SYS_PREBUILT_NASM=1 убирает требование NASM", initiative: "kaeru")

# на потом
task(body: "проверить rustc -vV на машине Сбера", due: "2d", initiative: "kaeru")
```
